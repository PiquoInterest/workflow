# Rust migration security record
#
# Security-relevant TypeScript behavior discovered during the Rust migration is
# recorded in docs/rust-port/TYPESCRIPT_LOGIC_AND_SECURITY_FIXES.md. Every item
# must identify the original behavior, impact, replacement behavior, regression
# tests, and repository-wide retirement condition.
#
# WF-RUST-005: TypeScript StepSchema models lifecycle-dependent fields as
# independently optional. It therefore accepts contradictory records such as a
# pending step with terminal output, a running step with completedAt, or a
# failed step with output and no error. The TypeScript characterization test
# keeps those unsafe acceptances reproducible. Rust uses a status-discriminated
# StepState enum and rejects forbidden, missing, and null-smuggled fields before
# a record reaches a Rust World. Validation errors never reflect payload data.
#
# WF-RUST-011: Hook resume protocol revisions previously accepted zero,
# negative, fractional, and out-of-range JavaScript numbers. A value such as
# 1.5 could satisfy a >= 1 capability gate despite having no defined protocol
# contract. TypeScript and Rust now require positive unsigned 32-bit integers,
# and the Rust boundary normalizes integral JSON forms to exact integer output.
# Direct Rust, TypeScript-oracle, and differential tests cover the accepted and
# rejected boundaries.
#
# WF-RUST-012: TypeScript StepSchema accepts negative, fractional, and
# above-safe-integer attempt counters because the field uses unconstrained
# z.number(). Steps are created at attempt zero and incremented on each start,
# so Rust preserves zero while requiring every persisted attempt to be an exact
# unsigned JavaScript-safe integer. This prevents retry accounting from moving
# backwards, representing partial attempts, or losing identity above 2^53 - 1.
# Direct Rust, TypeScript characterization, and differential tests cover the
# accepted and rejected boundaries without reflecting rejected values.
#
# WF-RUST-013 (TDD RED): AI provider stream chunks are an untrusted protocol
# boundary. Malformed tool-call JSON must be preserved as raw input instead of
# crashing the workflow or silently becoming a different argument object, and
# partial response-metadata chunks must merge without erasing earlier identity
# fields. The complete 30-declaration TypeScript suite is translated at
# rust/tdd/workflow-ai/tests/do_stream_step.rs. Rust implementation remains
# intentionally RED until those tests can pass against the real stream state
# machine; a panic marker is not treated as a security fix.
#
# WF-RUST-014 (TDD RED): AI telemetry can contain prompts, model output,
# reasoning, tool arguments, and tool results. The Rust port must preserve the
# TypeScript privacy controls: recordInputs=false omits prompt material and
# recordOutputs=false omits response text, tool-call arguments, and tool results
# while retaining non-sensitive usage and finish metadata. All nine current
# TypeScript telemetry assertions are translated at
# rust/tdd/workflow-ai/tests/telemetry.rs. This remains an implementation gate,
# not a closed security finding, until the actual Rust span path passes it.
#
# WF-RUST-015 (TDD RED): Provider metadata carried by tool calls and reasoning
# is execution-relevant state. Gemini thought signatures, OpenAI item IDs, and
# other provider fields must survive the assistant-message reconstruction used
# for the next model turn. Dropping or cross-assigning this metadata can break
# provider validation or associate opaque authorization/state tokens with the
# wrong parallel call. All 15 current iterator assertions, including malformed
# input retention and per-call metadata separation, are translated at
# rust/tdd/workflow-ai/tests/stream_text_iterator.rs. Closure requires the real
# Rust iterator and prompt builder to pass; the expected panic is not a fix.
#
# WF-RUST-016 (TDD RED): Chat reconnection consumes partially overlapping,
# attacker-influenced stream windows. Negative tail offsets must resolve with
# checked arithmetic and safely fall back when the server header is absent or
# invalid. Orphan deltas and outputs must not reach the UI consumer without a
# matching start/full-input chunk, while self-contained tool calls remain
# valid. Abort signals must survive send-to-reconnect transitions, and error
# formatting must never collapse structured failures to "[object Object]".
# All 23 current TypeScript transport assertions are translated at
# rust/tdd/workflow-ai/tests/workflow_chat_transport.rs. The finding remains an
# implementation gate until the real Rust transport passes those tests.
#
# WF-RUST-017 (TDD RED): Tool approval is an authorization boundary. A tool
# marked needsApproval, including a dynamic predicate, must receive the
# validated tool input and pause before execution; no tool result may exist
# until approval is supplied. Lifecycle and telemetry listeners must run in the
# defined order, but a failing telemetry integration must not abort an otherwise
# valid workflow stream. Abort/timeout signals and detailed token accounting
# must also survive the compatibility layer. The complete DurableAgent
# compatibility suite is translated at
# rust/tdd/workflow-ai/tests/durable_agent_compat.rs. The full runtime
# characterization at rust/tdd/workflow-core/tests/e2e_agent/gaps.rs proves the
# current TypeScript E2E executes riskyTool without approval, while a separate
# Rust-only target requires a pending call, zero results, and no execution.
# Full analysis and closure requirements are recorded in
# docs/rust-port/findings/WF-RUST-017.md. Closure requires the real Rust agent
# loop, callbacks, approval state machine, storage, resume, and replay paths.
#
# WF-RUST-018 (TDD RED): Tool execution origin and validated input are trust
# boundaries. Provider-executed tools must never invoke a same-named local
# implementation. Schema-invalid local input must not execute; it is returned
# to the model as an error-text result so a corrected retry can execute exactly
# once. Client-only tools pause the loop without fabricating a result. Context,
# repaired inputs, provider results, and parallel calls must remain associated
# with the correct call ID. UI collection must stay independent of finish-chunk
# emission so sendFinish=false cannot leak or synthesize terminal output. All
# 48 current TypeScript assertions are translated under
# rust/tdd/workflow-ai/tests/durable_agent/. Closure requires the real Rust
# agent loop, tool dispatcher, repair path, callbacks, and UI stream writer.
#
# WF-RUST-019 (TDD RED): Abort-reason hydration is part of the cancellation
# boundary. Before the TypeScript fix, scheduleWhenIdle could serialize a later
# step's signal as aborted=false while asynchronous reason hydration was still
# in flight, allowing work to continue after cancellation. The Rust test at
# rust/tdd/workflow-core/tests/abort_replay_ordering.rs requires the abort
# delivery to hold the idle gate, preserve the reason, and release its pending
# counter on every exit. Full analysis is in
# docs/rust-port/findings/WF-RUST-019.md; the finding remains open for Rust until
# the real event consumer and hydration path pass it.
#
# WF-RUST-020 (TDD RED): Permanently missing event payloads are corruption, not
# transient transport failures. Retrying them can turn one missing object into
# sustained read amplification and queue starvation; one captured run made
# 12,932 reads in 26 minutes. The Rust classification test requires a typed
# CorruptedEventLog error to be terminal while retaining retries for 429, 5xx,
# TRANSPORT, and TIMEOUT. Full analysis is in
# docs/rust-port/findings/WF-RUST-020.md. Closure requires the production stream
# parser and redelivery policy to consume the typed classification.
#
# WF-RUST-021 (TDD RED): Authenticated workflow encryption requires exact
# 32-byte keys, fresh 12-byte nonces, a 16-byte GCM tag, and typed failures for
# truncation, tampering, wrong keys, and invalid key usage. The Rust suite at
# rust/tdd/workflow-core/tests/encryption.rs also requires low-level diagnostics
# to avoid treating nonce bytes as a serialization format prefix. Full analysis
# is in docs/rust-port/findings/WF-RUST-021.md. Closure requires the production
# Rust serialization path and cross-language encrypted fixtures.
#
# WF-RUST-022 (TDD RED): Context errors are persisted and logged state. Internal
# functionName fields must not be enumerable, stored messages and stacks must
# contain no ANSI control bytes, and lazy terminal rendering must not duplicate
# framed details. All four context violations remain fatal because replay
# cannot repair a wrong calling context. The Rust suite at
# rust/tdd/workflow-core/tests/context_errors.rs also requires caller-directed
# stack capture. Full analysis is in
# docs/rust-port/findings/WF-RUST-022.md. Closure requires production error,
# serialization, rendering, and fatal-classification paths.
